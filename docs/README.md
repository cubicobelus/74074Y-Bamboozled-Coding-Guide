# Docs — which file do I open?

| I want to... | Open this |
| --- | --- |
| **Read the guide on my phone/Chromebook, with clickable navigation** | The Google Doc — link in the main [README](../README.md) |
| **Read the guide on GitHub, in a browser** | [`74074Y_Drivetrain_Guide.md`](74074Y_Drivetrain_Guide.md) — click it, then click the outline icon (top-right of the file view) for a clickable table of contents |
| **Print the guide, or open it in Word** | [`74074Y_Drivetrain_Guide.docx`](74074Y_Drivetrain_Guide.docx) |
| **Fill in a tuning log while testing the robot** | [`PID_Tuning_Log.docx`](PID_Tuning_Log.docx) — print it, or open it in Word/Google Docs and type directly into the tables |
| **Read the tuning log on GitHub** | [`PID_Tuning_Log.md`](PID_Tuning_Log.md) |

**New here?** Start with the Guide (Google Doc or `.md`), not the tuning log — the tuning log only makes sense once you've reached Part 1, Step 7 of the guide.

## Why both a `.docx` and a `.md` of the same thing?

- The **`.docx`** is the source file. If you edit the guide, edit this one, then re-upload it to Google Drive so the shared Google Doc stays current.
- The **`.md`** is a plain-text mirror kept in sync by hand, so the guide is actually readable directly on GitHub (real headers, tables, and code blocks) instead of GitHub's flat `.docx` preview.

If you edit one, mirror the change into the other — see the main README's "Keeping the docx and Google Doc in sync" section.
